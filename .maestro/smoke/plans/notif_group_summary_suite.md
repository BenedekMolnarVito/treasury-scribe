## Findings / risk ranking

**P0: fix incomplete, not a precedence bug.** `NotificationListenerPlugin.kt:141–159` independently enumerates active notifications without package/summary filtering. `App.tsx:150–175,335–337` ingests those on bootstrap. Summary flags disappear from the TS bridge (`src/plugins/NotificationListenerPlugin.ts:18–31`); TS cannot recover them. NG16/NG17 deliberately specify desired fix acceptance and are expected RED on current HEAD. Do not turn predicted buggy row counts into green acceptance. Source-level proof, not executed reproduction.

**Precedence resolved:** Kotlin infix calls bind tighter than equality `!=`. Exact expression means `((sbn.notification?.flags ?: 0) and Notification.FLAG_GROUP_SUMMARY) != 0`; Int.and(Int) yields Int, compared to zero yields Boolean. It is valid Kotlin, not Int.and(Boolean). Official grammar https://raw.githubusercontent.com/Kotlin/kotlin-spec/release/grammar/src/main/antlr/KotlinParser.g4: equality → comparison → genericCallLikeComparison → infixOperation → elvisExpression → infixFunctionCall. Parenthesized Elvis receiver prevents nullable ambiguity. Compilation itself still requires native compile gate; no compile run claimed here.

**P1: startup queue/event race.** Service.kt:100 filters before enqueue :117–119, so summary cannot enter pending queue through posted callback. Plugin.kt:24–30 flushes at plugin load, potentially BEFORE JS addListener (`App.tsx:297`). notifyListeners has no retainUntilConsumed argument. Children may lose events, active snapshot recovers active children only, and reintroduces summaries. In-memory queue lost on service destruction (:57–60); dismissed children cannot be recovered from active snapshots. App focus handler :351–359 only ensures monitoring; contrary to copilot prose, it does not refresh active notifications on every focus. Bootstrap and passed pull-refresh callback are actual snapshot entry points.

**P1: suppression policy/data loss.** Every explicit app summary with real transaction content drops (:100). Correct current-code expectation zero; desired financial treatment EXPECTED=UNSPECIFIED. Native-id update/dismiss/repost semantics likewise unspecified: id/key absent from payload, text/time dedup controls persistence. Different-id identical spends within five seconds collapse; same-id changed content creates another row.

Remaining risks: OS autogroup threshold/version/OEM differences; child callbacks repeated during grouping; summary cancellation/repost; empty non-summary still persisted; title digits/balance/FX parser regression; ±1s snapshot vs ±5s event windows; whole-text DOM falsely matching body amounts.
